# 公众号菜单设计

> 公众号后台"自定义菜单"配置参考。
> 微信公众号自定义菜单:3 个一级菜单,每个最多 5 个二级菜单。

## 菜单结构(总)

```
┌─ 草稿本 ─┐    ┌─ 草稿碎片 ─┐    ┌─ 关于小凡 ─┐
│  最新文章 │    │  未发草稿  │    │  我是谁    │
│  文章目录 │    │  思考碎片  │    │  公众号说明│
│  RSS 订阅 │    │  画废的图  │    │  联系方式  │
└──────────┘    └────────────┘    └───────────┘
```

## 3 个一级菜单设计

### 1. 草稿本(主菜单)

| 二级菜单 | 跳转内容 | 类型 |
|----------|----------|------|
| **最新文章** | 最新一篇(动态更新,需要自动化) | 跳转文章链接 |
| **文章目录** | 公众号历史文章合集(爬取公众号文章) | 跳转页面 |
| **RSS 订阅** | 给 RSS 地址(邮箱订阅) | 跳转链接 |

**当前实现(初期手动)**:
- "最新文章" → 手动改成最新一篇的链接
- "文章目录" → 手动列历史文章(每 5 篇做一次合集)
- "RSS 订阅" → 暂时禁用(等公众号 API 跑通后启用)

### 2. 草稿碎片

| 二级菜单 | 跳转内容 | 类型 |
|----------|----------|------|
| **未发草稿** | 还在筹备中 | 暂不挂 |
| **思考碎片** | 朋友圈 / 即时想法(短内容) | 暂不挂 |
| **画废的图** | xiaofan-ink 出图失败的图,展示"过程" | 暂不挂 |

**当前实现(初期)**:
- 整个二级菜单先**不挂任何内容**,或挂一个"筹备中"占位文
- 等系列稳定 5-10 篇后再开"碎片"区

### 3. 关于小凡

| 二级菜单 | 跳转内容 | 类型 |
|----------|----------|------|
| **我是谁** | brand/README.md 的"关于小凡"段 | 跳转文章 |
| **公众号说明** | brand/README.md 全文 | 跳转文章 |
| **联系方式** | 公众号留言 + GitHub Issues | 跳转链接 |

**当前实现**:
- "我是谁" → 跳转 brand/README.md 的 §1 头像 / §2 欢迎语,或写一篇专门文章
- "公众号说明" → 跳转 brand/README.md
- "联系方式" → 跳转 GitHub Issues 页面

## 自动化建议(后续)

### "最新文章"自动化

公众号 API 每个月有群发次数限制(订阅号 1 天 1 次),如果用 API 自动同步:

```python
# 伪代码
latest = read_latest_essay("doc/essays/")
push_to_wechat_menu(latest.title, latest.url)
```

但手动维护更稳(死板冷静调性也不追求自动化),可以**每发布一篇手动更新一次菜单**。

### "文章目录"自动化

可以用公众号"页面模板"功能,做一个小程序页面:
- 列历史文章
- 按时间倒序
- 点击跳到具体文章

或用 Notion / GitBook / 静态网站当后端,公众号菜单跳到外链。

## 菜单文案规则

- 菜单名**短**(2-4 字),一眼能看清
- 不用"点我" / "进入" 这类多余动词
- 不用 emoji(死板冷静调性,emoji 会破坏)
- 调性一致,菜单名跟"草稿" / "本" / "碎片" 主题词强关联

## 跟 xiaofan-ink skill 的衔接

后续如果公众号跑通 API,可以用 skill 自动化:
- `xiaofan-ink/articles-to-wechat.py` — 把 `doc/essays/00X-*.md` 推到公众号
- 菜单"最新文章" 自动同步

这部分可以加在 `xiaofan-ink/tools/` 目录下(目前还没有,后续扩展时建)。
